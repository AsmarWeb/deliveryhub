# Merchant and driver notification center

Requires the automatic dispatch release. No new dependencies, environment variables, migration, queue worker or OpenAI access.

The existing after-commit database listener now informs merchants when a price is ready, driver search starts/restarts, an offer is sent, accepted, picked up, in transit, delivered, completed or cancelled. Drivers receive their new pending-offer notification. UUIDs remain stable per history and recipient to prevent duplicate delivery on replay. New assignment histories store assignment_id; replays resolve that exact offer even if another driver is offered the order later. Legacy histories retain the existing pending-offer fallback. The assignment ID is included only in the offer recipient's notification, not the merchant payload.

Merchant home unread counter opens /merchant/notifications. Driver Alerts tab shows an unread badge. Both roles share a bilingual center, mark-one/mark-all actions, pagination and inline errors. Messages explain status and include tracking number. Merchant opens its delivery, driver opens its original assignment; older driver notifications without an assignment ID open own Orders. Targets accept only positive safe integer IDs and never server-provided URLs; backend ownership checks remain authoritative. Old offers may be expired/rejected when opened and must not be accepted from notification text alone.

Counters poll every 20 seconds while focused and foregrounded, refresh after successful local read actions and on foreground return. Failed counter requests preserve the previous value; an unknown merchant count displays a dash. First-page center contents refresh every 20 seconds while focused/foregrounded and idle. After loading more pages, pull to refresh for new content. Timestamps display Asia/Dubai. Notification reads and listing remain scoped to the authenticated user.

These are in-app database notifications, not Push, background alerts, sounds or guaranteed instant delivery. No phone notification is sent while the app is closed. No historical backfill; existing notifications remain readable.

Validation: six new mobile tests (43 total), TypeScript/lint and all-platform Expo export. Two additional Laravel tests plus updated integration expectations cover the new statuses, idempotency and original offer identity on replay. PHP syntax parsed; PHP runtime tests must run in Docker on the developer machine. Manual acceptance: separate merchant/driver sessions, approve price, enable eligible driver dispatch, trigger automatic offer, verify badge/list/detail, accept and deliver, verify merchant updates; read one/all, navigate away/back, disconnect/reconnect and background/foreground. No authenticated visual or real-device claim is made by export success.
